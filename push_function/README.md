# دالة إرسال Push الخارجية — رعاية

دالة واحدة صغيرة (`api/send-push.js`) تُنشَر على **Vercel** (مجاني بالكامل)
مهمّتها الوحيدة: إرسال إشعار Push حقيقي عبر Firebase Cloud Messaging لمعلمة
واحدة محددة، بعد إعادة التحقق الكامل من صلاحية المُرسِلة على الخادم.

**لماذا خارج Firebase نفسه؟** لأن إرسال Push لتوكن جهاز محدد يتطلب بيانات
اعتماد "حساب خدمة" (Service Account) موثوقة تماماً — شرط أمان من Google لا
يمكن تنفيذه من داخل تطبيق العميل (لا Flutter ولا الويب). وحل Firebase
الرسمي لهذا (Cloud Functions) غير متاح إطلاقاً على خطة Spark المجانية،
فاستُبدل بدالة خارجية مجانية على Vercel تُبقي مشروع Firebase على Spark
بالكامل بلا أي تغيير في خطته.

هذه الخطوات كلها **تنفّذينها بنفسك خارج المحادثة** (تسجيل دخول، مفاتيح
حساسة، بطاقات — لا يجوز لأي مساعد أن يطّلع عليها أو يُدخلها نيابة عنك).

---

## 1) توليد مفتاح حساب الخدمة (Service Account) من Firebase

1. افتحي [Firebase Console](https://console.firebase.google.com) → مشروع
   **daftar-alhalaqah** → ⚙️ إعدادات المشروع → تبويب **حسابات الخدمة
   (Service Accounts)**.
2. اضغطي **"إنشاء مفتاح خاص جديد" (Generate new private key)** — سيُنزَّل
   ملف JSON على جهازك (احتفظي به سرّياً تماماً، لا تشاركيه مع أحد ولا
   تضعيه في أي مستودع Git).

## 2) تثبيت أداة Vercel ونشر الدالة

من الطرفية (Terminal)، داخل مجلد `push_function` بالضبط:

```bash
npm install -g vercel     # مرة واحدة فقط إن لم تكن مثبَّتة
cd push_function
vercel login              # سجّلي دخولك (يفتح المتصفح، مجاني)
vercel                     # اربطي المجلد بمشروع Vercel جديد (اتبعي الأسئلة، القيم الافتراضية تكفي)
```

## 3) ضبط متغيّر البيئة (السر الوحيد الذي تحتاجه الدالة)

```bash
vercel env add FIREBASE_SERVICE_ACCOUNT_JSON production
```

عندما تُطلَب منك القيمة: افتحي ملف الـ JSON الذي نزّلتِه في الخطوة ١
بمحرر نصوص، انسخي **محتواه بالكامل** (سطر واحد طويل أو كما هو) والصقيه.
كرّري نفس الأمر مع `preview` و`development` إن أردتِ تجربة الدالة محلياً
لاحقاً (اختياري تماماً).

## 4) النشر الفعلي

```bash
vercel --prod
```

سيُعطيكِ رابطاً نهائياً شبيهاً بـ:
`https://raaya-push-function.vercel.app`

**نقطة النهاية (Endpoint) الفعلية التي تحتاجينها في الخطوة التالية هي هذا
الرابط + `/api/send-push`**، مثال:
`https://raaya-push-function.vercel.app/api/send-push`

## 5) توليد مفتاح Web Push (VAPID) — لازم فقط لتشغيل الإشعارات على الويب

1. Firebase Console → ⚙️ إعدادات المشروع → تبويب **Cloud Messaging**.
2. تحت قسم **Web configuration → Web Push certificates**، اضغطي
   **"إنشاء زوج مفاتيح" (Generate key pair)**.
3. انسخي القيمة الظاهرة (تبدأ عادة بحروف وأرقام طويلة).

## 6) حفظ القيمتين في Firestore (خطوة واحدة، مرة واحدة فقط)

بما أن مجموعة `app_config` محمية بقاعدة `allow write: if false` (لا يمكن
كتابتها من أي تطبيق عميل مطلقاً، لا حتى من حساب مشرفة)، يجب إضافة المستند
يدوياً من Firebase Console مباشرة:

1. Firebase Console → **Firestore Database** → أنشئي مجموعة باسم
   `app_config` (إن لم تكن موجودة) → مستند بمعرّف **`push`** بالضبط.
2. أضيفي فيه حقلين نصّيين (`string`):
   - `vercelEndpointUrl` = الرابط الكامل من الخطوة ٤ (مع `/api/send-push`)
   - `webVapidKey` = المفتاح من الخطوة ٥

بمجرد حفظ هذا المستند، تبدأ الإشعارات في العمل فوراً بلا حاجة لأي بناء
جديد للتطبيق (القيمتان تُقرآن من Firestore مباشرة عند الحاجة).

---

## اختبار سريع للدالة نفسها (اختياري)

بعد النشر، يمكنك التأكد أنها تستجيب (سترفض الطلب لأنه بلا بيانات حقيقية،
لكن هذا يكفي للتأكد أنها منشورة وتعمل):

```bash
curl -i -X POST https://<رابطك>/api/send-push \
  -H "Content-Type: application/json" \
  -d '{"idToken":"test","notificationId":"test"}'
```

استجابة متوقّعة: `401 {"error":"invalid_id_token"}` — هذا يعني أن الدالة
تعمل فعلاً وتتحقق من الهوية بشكل صحيح (وليس أنها معطَّلة).

## ماذا لو أردتِ تغيير الدالة لاحقاً؟

عدّلي `api/send-push.js` ثم شغّلي `vercel --prod` مرة أخرى من نفس المجلد —
لا حاجة لإعادة ضبط متغيّر البيئة إن لم يتغيّر مفتاح حساب الخدمة.
